# Issue tracker: GitHub

Status: active normative
Authority: repository governance
Last verified: 2026-09-10

GitHub Issues remain the durable task records for this repository. Project 4,
now named `Legacy AI Workspace Delivery — frozen`, is a frozen legacy planning
layer and is not Cortxt's active roadmap. Do not add, reclassify, or dispatch
work from it without a separate operator decision. Use the repository remote to
resolve `rian010194/cortxt` and use `gh` for tracker
operations.

## Current workflow-state availability

The workflow-state carrier is GitHub Issue labels (ADR-018):
`workflow:inbox`, `workflow:ready`, `workflow:in-progress`, `workflow:review`,
`workflow:blocked`, `workflow:done`. Project 4 is frozen and no longer used.
An issue carries exactly one `workflow:*` label at a time.

The state names below define the required lifecycle contract, now backed by the
label carrier above.

## Conventions

- Create an issue with a descriptive title and structured Markdown body.
- Read the issue, labels, assignees, dependencies, comments, and any explicitly
  designated current planning state before acting.
- Use these workflow states via the `workflow:*` labels: `Inbox`, `Ready`,
  `In progress`, `Review`, `Blocked`, and `Done`.
- Treat authoritative `Ready` as execution approval only when scope, acceptance
  criteria, worker role, time limit, cost limit, and human approval are present.
- Record runtime identity and evidence using the repository's `docs/architecture/dispatch-contract.md`.
- Pull requests are not a request or triage surface.

## Wayfinding operations

Atlas is the planning-map mechanism (#210). See `docs/agents/atlas.md` for the
map structure, relation contract, section ownership and sync rules. In short:
one global roadmap map (`Area: Global`) and one map per roadmap area, both
labelled `atlas:map`, regenerated by `scripts/atlas_sync.py`
(`.github/workflows/atlas-sync.yml`, manual plus daily).

Atlas ties goals, areas, dependencies and progress together as **derived**
views: it renders what the issues already say -- current state, execution path,
blockers, the actionable frontier, milestone progress, relationship drift and
review evidence -- so the shape of the work is legible without reading every
issue. Issues remain the single source of truth. A map never grants authority,
never carries workflow state, and is never a second backlog. Content inside the
`atlas:auto` markers is regenerated and must not be hand-edited.

The earlier ad-hoc `wayfinder:*` label convention is **superseded** by Atlas and
is no longer operating guidance. It survives only as historical context for
pre-Atlas map issues that are still open: those used one issue labelled
`wayfinder:map` as the canonical map, with `wayfinder:research`,
`wayfinder:prototype`, `wayfinder:grilling` and `wayfinder:task` children. Do
not create, dispatch from, or extend `wayfinder:*` issues; migrate anything
still live to Atlas and the `workflow:*` carrier.

## Safety

- Creating or dispatching child work requires the operator-approved map and ticket.
- A runtime card or delegation handle is never a second backlog item.
- Do not copy secrets, private documents, full prompts, or model reasoning into issues or comments.
